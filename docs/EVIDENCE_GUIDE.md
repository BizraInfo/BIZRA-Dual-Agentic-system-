# BIZRA v7.0 Evidence Guide & Reproducibility

## 1. The Evidence Pack

The Evidence Pack is a cryptographically sealed bundle that proves a system execution was performed under constitutional constraints. It is generated by the `produce_evidence_pack.sh` script.

### Contents of `evidence_pack_<timestamp>.json`

- `input_hash`: SHA-256 of the input prompt/task.
- `attestation`: TPM 2.0 quote for PCR 12-15.
- `metrics`: Final SNR and Ihsān scores from the execution.
- `signature`: Merkle root signature from the Sovereign Kernel.

## 2. Verification Steps (The Auditor's Path)

To verify the integrity of a BIZRA execution, follow these steps:

### Step A: Verify Input Grounding

Ensure the `task` in the evidence pack matches the hash of your input.

```bash
python3 scripts/verify_attestation.py --input "your prompt" --pack evidence_pack_X.json
```

### Step B: Validate TPM Quote

The quote proves the code was running on a pinned kernel version with specific PCR measurements.

- **PCR 15** must match the current Genesis hash: `3b2d8601aec6422a6d...`

### Step C: Audit Ihsān Compliance

The `ihsan_score` must be ≥ 0.95. If lower, the system should have rejected the request. Check the `sat_contributions` for veto reasons.

## 3. Achieving Reproducibility

BIZRA ensures "Reasoning Determinism" through:

- **Fixed RNG Seeds**: All internal agentic variance is seeded from the input hash.
- **Fixed-Point Arithmetic**: `Fixed64` prevents floating-point drift across different CPU architectures.
- **Pinned Dependencies**: `Cargo.lock` ensures the exact compiler and library versions.

## 4. Troubleshooting Rejections

If an evidence pack contains a `rejection_receipt`:

1. Check `rejection_code`:
   - `IhsanUnsat`: The ethics threshold was not met.
   - `ThermalThrottle`: The CPU was too hot (safety hardware gate).
   - `FormalVerificationFailure`: Z3 proved an invariant violation.
2. Review the `trace` in the evidence logs to see which SAT agent triggered the VETO.
